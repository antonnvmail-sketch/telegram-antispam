# Работа с публичной копией

- Перед изменениями читать README.md и CHANGELOG.md. Это отдельная публикационная копия, не каталог работающего бота.
- Не добавлять секреты, рабочие датасеты, БД, модели, логи, резервные копии и личные данные. data.example.txt содержит только вымышленные примеры.
- Не подключаться к реальному Telegram и не использовать рабочий токен при проверках. Тесты выполняются на временных путях с подменой внешних действий.
- Сохранять DRY_RUN=true по умолчанию. Не утверждать точность по обучающим данным; независимая оценка остаётся отдельной задачей.
- После существенных изменений обновлять существующие README/CHANGELOG и выполнять соответствующие проверки. Различать подготовку, проверку, публикацию и развёртывание.

## Описания релизов и языки

- При каждом обновлении версии одновременно обновлять `README.md` и `README.en.md`, включая описание новой версии, команды, ограничения и ссылки. Если описание изменено на одном языке, сверить и обновить второй до завершения задачи.
- Английский README — приоритетный публичный документ для международной аудитории и поиска. Он должен быть полным, естественно написанным и не уступать русскому по фактам, инструкциям и истории; не заменять его краткой выжимкой.
- Для каждой версии добавлять отдельные «Что нового в …» / «New in …». Сохранять предыдущие версии и их номера, не заменять их массовой сменой номера по всему документу.
- Перед публикацией сопоставить список и порядок версий в двух README, полноту возможностей/ограничений и ссылки. Пропущенный раздел в одном языке означает, что релиз ещё не готов.
- Проверять окончательный коммит, выбранный тег и скачиваемый архив до публикации, а не только README основной ветки. Изменения документов после публикации отражать в истории, архиве и контрольной сумме; не приписывать старому неизменённому тегу новые документы.
